## Step 2 — signing

Option a) (an Apple grant for this project's own App ID) is not requested yet. See `aoe2/entitlement.md`.

Option b), ad-hoc mode, is implemented (*built*, *runtime passed*). On this macOS 27.0.1 install, an ad-hoc signature
carrying the managed `com.apple.developer.cross-architecture-support` passes the P0 probe. The probe and its table are
in `aoe2/entitlement.md`. Wine patch 0007 checks that name, so no Wine patch changes.

- `MACNEUTRON_ADHOC=1` (`wine-arm64/lib.sh`) refuses to build unless `csrutil status` reports disabled and the boot
  arguments set `amfi_get_out_of_my_way`. It also refuses if either Developer ID variable is set. It sets the signing
  identity to `-`, so its build stamp differs from a Developer ID build's.
- The loader is signed with `wine-arm64/wine-adhoc.entitlements`: the cross-architecture entitlement and the three
  `cs.*` keys, without the maintainer's App ID and team. No provisioning profile is embedded.
- `bundle.sh` checks that each Mach-O has `Signature=adhoc`, in place of the secure timestamp. It marks
  `Info.plist` with `MacNeutronSigning = adhoc-sip-amfi-disabled-only` and refuses `--release`.
- `tests/profile_test.sh` covers the mode with 8 cases against a faked host: accepted twice, then SIP enabled, no
  AMFI boot argument, `amfi_get_out_of_my_way=0`, identity set, profile set, and the default entitlements file. A
  mutation that accepts `amfi_get_out_of_my_way=0` turns it red.
